# 감정 일기

React와 Supabase로 만든 감정 기록 웹앱입니다. 하루의 감정과 생각을 기록하고, 새로고침하거나 다른 기기에서 접속해도 Supabase에 저장된 동일한 일기 목록을 확인할 수 있습니다.

## 주요 기능

- 😊 기쁨, 😌 평온, 😢 슬픔, 😠 화남, 😰 불안 중 감정 선택
- 일기 작성 및 Supabase 저장
- 작성일시 기준 최신순 목록 조회
- 감정별 필터링
- 일기 삭제
- 목록 조회, 저장, 삭제 중 상태 표시
- 기록이 없거나 필터 결과가 없을 때 빈 상태 안내
- 네트워크, 환경 변수, Supabase 요청 실패 시 오류 안내
- 모바일과 데스크톱을 지원하는 반응형 UI

작성 및 삭제가 끝나면 목록을 다시 조회합니다. Supabase Realtime이나 웹소켓 구독은 사용하지 않습니다.

## 기술 스택

- Vite
- React
- Tailwind CSS v4
- `@supabase/supabase-js`
- Supabase PostgreSQL

## 시작하기

### 1. 저장소와 의존성 설치

```bash
git clone <repository-url>
cd 26-w09-diary
npm install
```

### 2. 환경 변수 설정

`.env.example`을 복사해 `.env.local`을 만들고 Supabase 프로젝트 값을 입력합니다.

```bash
cp .env.example .env.local
```

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxxxxx
```

`.env.local`은 Git에 커밋하지 않습니다. Vite의 `VITE_` 환경 변수는 브라우저 번들에 포함되므로 `service_role` 키나 기타 비밀 키를 입력하면 안 됩니다.

### 3. 개발 서버 실행

```bash
npm run dev
```

기본적으로 표시되는 로컬 주소는 `http://localhost:5173`입니다.

## Supabase 데이터베이스

이 앱은 이미 생성된 `diaries` 테이블을 사용합니다.

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| `id` | `bigint` | 자동 생성되는 일기 ID |
| `content` | `text` | 필수 일기 본문 |
| `emotion` | `text` | `joy`, `calm`, `sad`, `angry`, `anxious` 중 하나 |
| `created_at` | `timestamptz` | 작성 시각, 데이터베이스 기본값 사용 |

Supabase SQL Editor에서 테이블을 새로 만들어야 하는 경우에는 다음과 같이 설정할 수 있습니다.

```sql
create table public.diaries (
  id bigint generated by default as identity primary key,
  content text not null,
  emotion text not null check (emotion in ('joy', 'calm', 'sad', 'angry', 'anxious')),
  created_at timestamptz not null default now()
);
```

앱의 데이터 함수는 [src/api/diaries.js](./src/api/diaries.js)에 있으며, 조회·추가·삭제 요청만 제공합니다. Supabase 클라이언트는 [src/lib/supabase.js](./src/lib/supabase.js)에서 한 번만 생성합니다.

## 보안 및 RLS 주의사항

- Supabase URL과 publishable key는 프런트엔드 앱에서 사용하도록 공개되는 값입니다. 대신 데이터 접근 권한은 Supabase의 RLS(Row Level Security) 정책으로 제한해야 합니다.
- `.env.local`은 `.gitignore`에 포함되어 있으므로 저장소에 올리지 않습니다.
- 브라우저 개발자 도구나 배포된 JavaScript에서 publishable key를 볼 수 있는 것은 정상입니다. 이 키 자체를 비밀로 취급하는 것이 아니라, RLS 정책과 인증으로 데이터를 보호해야 합니다.
- 인증 없이 `using (true)` 정책으로 누구나 조회·추가·삭제할 수 있도록 설정하면 모든 방문자가 모든 일기를 읽고 삭제할 수 있습니다. 개인별 일기 보호에는 적절하지 않습니다.
- 실제 서비스에서는 Supabase Auth를 사용하고 `user_id` 컬럼을 추가한 뒤, `auth.uid() = user_id` 조건으로 조회·추가·삭제 정책을 제한해야 합니다.

예를 들어 인증 기반 정책을 사용하려면 다음과 같은 방향으로 설계합니다.

```sql
-- diaries 테이블에 user_id uuid references auth.users(id) 컬럼을 추가한 뒤 적용합니다.
create policy "Users can read their own diaries"
on public.diaries for select
using (auth.uid() = user_id);

create policy "Users can create their own diaries"
on public.diaries for insert
with check (auth.uid() = user_id);

create policy "Users can delete their own diaries"
on public.diaries for delete
using (auth.uid() = user_id);
```

현재 앱은 익명 사용자별 인증을 구현하지 않았으므로, 공개 데모에서는 민감한 개인정보나 사적인 내용을 입력하지 않는 것이 좋습니다.

## 프로젝트 구조

```text
src/
├── api/
│   └── diaries.js       # diaries 조회·추가·삭제 API
├── lib/
│   └── supabase.js      # Supabase 클라이언트 초기화
├── App.jsx              # 작성, 목록, 필터, 상태 처리
├── App.css              # 화면 컴포넌트 스타일
├── index.css            # 전역 스타일 및 Tailwind import
└── main.jsx             # React 앱 진입점
```
